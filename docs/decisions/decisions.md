# Decisions

Status: `accepted`, `proposed`, `open`.

| # | Decision | Status | Why |
|---|---|---|---|
| 1 | **Tools:** MCP for third-party (Gmail, Calendar, Drive, Playwright). Native functions for own tools (memory, todos, termusic, OS, scheduler). One `ToolRegistry`. | accepted | MCP is a plugin standard, not a requirement. Senku's private in-process MCP servers were overhead for nothing. Rust body (later) is a local MCP server. |
| 2 | **Brain:** no from-scratch agent runtime. Heavy work via Claude Agent SDK. Talker is a thin own loop with a fast model. Brain behind one interface. | accepted | Tool loop, permissions, MCP hosting are solved. Do not copy `--dangerously-skip-permissions` or shell-string prompts. |
| 3 | **Voice:** *Superseded in practice by 19-22:* Evie uses its own small loop (sounddevice mic, own loudness gate, faster-whisper, Kokoro), not Pipecat; Pipecat stays installed and may be used for barge-in later. Original text: Pipecat for VAD, STT, LLM, TTS, barge-in. Silero VAD. Push-to-talk first. STT Groq Whisper or Deepgram. TTS Edge first, Fish Audio after. | accepted (version verified; partly superseded) | Interruption and turn-taking are hard to build. Pipecat 1.16.0 installed on Py 3.12 Windows. STT decided: Groq Whisper (cloud, light, free key). TTS: now Kokoro-82M int8 local (kokoro-onnx, ~0.5-0.7 s/sentence, files in `models/kokoro/`, gitignored) first, Edge (custom service) as fallback, order set by `EVIE_TTS`; Piper/Fish not added. Browser Web Speech API considered, not chosen. |
| 4 | **Stack:** Python (brain, voice), Rust (Windows body), Go (gateway), React+TS (UI). Python plus bare web page first, others added in phases. `uv` for Python, `requires-python >=3.12,<3.14` (Pipecat resolution fails for 3.14). Do not add `openai` or `grpcio-tools` directly: they clash with Pipecat's `protobuf`/`typing-extensions` pins. Generate termusic proto stubs with a protoc matching protobuf 6.x. | accepted | Each language has one job. Rust and Go would delay a working voice if put in MVP. If Go is overhead, Python takes gateway back. |
| 5 | **Platform:** Windows only for v1. Voice in MVP. UI look decided later. | accepted | |
| 6 | **Notifications:** one native `notify()` to toast, ntfy, UI. Phone push only if away or long task. | accepted | From Senku ntfy. Fixes: long random topic or self-host, no sensitive body, signed one-time approve token, persist reminders in SQLite. |
| 7 | **Termusic:** gRPC client of `termusic-server` (`[::1]:5101`) using `player.proto`. | accepted | Server has pause, skip, volume (step 5), queue, shuffle, loop, seek. Gaps: no absolute volume, TogglePause flips state, queue needs path or URL, music drowns mic. |
| 8 | **Process model:** always-on Rust "ear" (tray, autostart, mic, wake word, VAD) plus Python brain, talking over a local WebSocket. No browser page needed for voice. Heavy Python modules and MCP servers load lazily; brain may be started on demand and stopped when idle. | accepted | Always-on and light. Cloud STT/LLM/TTS keep local cost to mic, wake word and a socket. Drops the browser-mic-page idea (needs an open tab, sends audio to Google all the time). |
| 9 | **Wake word:** openWakeWord (local ONNX, 80 ms frames, threshold plus cooldown), run in the Rust ear via `ort`. Stock "hey jarvis" first, custom "Evie" model trained later. | proposed | Read in binoy's Jarvis `wakeword.rs`. adewaskar's Jarvis regex-matches browser SpeechRecognition output instead. Custom-word training quality for "Evie" unverified. |
| 10 | **Tool contract:** every tool declares `risk` (read or write) and `fast` (fast-path eligible). Approval gate and fast router read this metadata. Tools never import agent or voice code. | accepted | New tools are added without touching the brain. The loop in `core/agent.py` can change later (own loop, LangGraph) with no tool changes. |
| 11 | **State:** SQLite from the start for sessions, reminders, tasks. **Modes** in config; `gaming` mode = quiet short replies, no automation tools, phone push for long results. | proposed | |
| 12 | **Game safety:** Evie stays a separate audio-only process. No hooking, screen capture, overlay or input injection while a game runs (Valorant uses the Vanguard kernel anti-cheat). | accepted | Rule of thumb. What Vanguard flags is unverified. |
| 13 | **Rust ear, Python brain:** Rust does only mic, wake word, VAD, tray, autostart. Python does STT, thinking, TTS, tools. Python voice gateway and a push-to-talk test client come first, so the brain is proven by voice before any Rust. Stay on Python 3.12 (3.15 is alpha; AI/audio packages lag). 3.15 has PEP 810 `lazy import` (verified on 3.15.0a7); until then use function-level imports for heavy modules and convert later. | accepted | Measured: idle Python with google-genai, numpy, onnxruntime is ~96 MB RSS (imports only, no pipeline). Rust is lighter for the always-on loop. Brain speed is network-bound, not CPU-bound. Own Rust code written against the openWakeWord spec; binoy's repo has no license. |
| 14 | **Tool creation:** LangChain `@tool` machinery (`langchain-core`, `parse_docstring=True`) wrapped by our `tool(risk, fast)` decorator. Schema and arg validation from type hints (pydantic), descriptions from Google-style `Args:` docstrings, constraints via `Annotated[T, Field(ge=, le=)]`. Provider schemas via `convert_to_openai_function`. `pydantic` is a direct dependency. | accepted | User choice. LangChain gives no risk/fast flags, so our wrapper adds them (kept in `Meta` and `tool.metadata`). Cost measured: `langchain_core.tools` +7 MB, 0.09 s; `langgraph.graph` +44 MB, 1.7 s (not imported by us). No pin clash with Pipecat (protobuf stays 6.33.6). LangGraph is installed via `langchain` but unused; brain stays a plain loop. |
| 15 | **Adding songs online = termusic's own `s` search, driven in the background and by voice.** Evie writes keys straight into the TUI process's console and reads its screen text (AttachConsole + WriteConsoleInput / ReadConsoleOutput, run in a short-lived child process). No focus, no pyautogui, keys can only reach termusic, safe in games. Flow: library miss -> offer search -> Evie types `s`, query, Enter -> reads the results popup -> speaks numbered options -> user says a number -> Evie presses Down/Enter -> termusic downloads -> a folder watcher queues and plays the new file. Evie has no downloader of its own; failures are reported, fixing termusic is the user's job. | accepted | User: voice assistant, nobody at the keyboard to pick. Verified live end to end (Hola Amigo). Screen scraping is brittle: the parser is pinned by a real capture in tests/fixtures. Needs focus on the library pane when `s` is pressed. Tests are guarded so they can never open windows or kill processes (they once opened 3 TUIs). |
| 16 | **Spoken text is cleaned deterministically** (`services/text.py`): drops Official Music Video, Lyrics, channel names after a bar, [video ids], underscores; keeps version tags (8D, slowed & reverb, feat., Remix). Applied to every title that is spoken or announced. | accepted | User: voice needs clean text. Rules not an LLM: instant and repeatable. The talker model already paraphrases when it speaks, but announcements bypass it. Word list is hand-written for English/Hindi titles. |
| 17 | **Web questions are answered, not redirected.** `web_search` returns a short answer plus up to 4 clean sources (ads dropped, one per site, trimmed); the talker speaks one or two sentences. `open_website` only when the user asks to see a page. Primary: Tavily (`TAVILY_API_KEY`, answer included, built for agents). Fallback without a key: keyless `ddgs`. | accepted | User: an assistant should summarize, not send you to a browser. Measured: Gemini Google-Search grounding gives 429 quota errors on the free key; keyless engines took 1.7-4.6 s and some returned nothing 2 times in 3 (duckduckgo/brave backends failed instantly), so keyless is not voice-grade. Tavily request follows its documented API but is not yet run against a real key. |
| 18 | **Wikipedia for stable facts** via LangChain's `WikipediaAPIWrapper` (user's pick; works in their research agent), cleaned to 1-2 spoken sentences. `web_search` for anything recent. The model chooses by tool description. | accepted | Direct calls to the Wikipedia API got 403 (Wikimedia requires a User-Agent with real contact details; a fake contact would defeat the point and I won't put the user's email in a header unasked). The `wikipedia` package that the wrapper uses sends an accepted User-Agent. Measured ~2 s per hit. Caveat: `langchain-community` announced it is being sunset; if removed, call the `wikipedia` package directly. It also pulled in sqlalchemy and pydantic-settings. |
| 19 | **Hands-free listening, no push-to-talk.** The mic stays open (one persistent stream); a loudness gate (threshold = 2.5x the rolling median of room noise, floor 250, `EVIE_THRESHOLD` overrides) starts and ends utterances, with 0.4 s pre-roll, blip and steady-noise filters. Printed stages: listening, listening done, STT time, You, brain time, Evie. | accepted | The user wants no key press. Costs: no wake word, so TV, music and other people can trigger it (and be transcribed). A wake word or hotkey is the planned fix (9, 13). |
| 20 | **STT: on-device first.** `faster-whisper` `base` (multilingual, int8, CPU) with `EVIE_LANG=auto` limited to en/hi so Hinglish works; Groq Whisper is the backup (keys rotate on 429/401). Library artist and song names are the Whisper prompt. `EVIE_STT`, `EVIE_STT_MODEL`, `EVIE_LANG`, `EVIE_LANGS`. | accepted, accuracy open | Measured 1.9 s clip: base 0.3-0.7 s, small 1-2 s and writes Hindi in Devanagari, Groq 0.4 s. Local keeps audio on the PC. The user finds base inaccurate on names ("Jo Tum Mere Ho"): decide from `scripts/stt_compare.py` on their voice. Rejected: the SpeechRecognition library (a wrapper; its free backend is Google's unofficial web API, cloud only). |
| 21 | **TTS: Kokoro local first, Edge fallback.** `kokoro-onnx` int8, 8 threads, `af_sarah` (female only, user's pick), `EVIE_TTS` order, `EVIE_TTS_SPEED`. Reply is spoken sentence by sentence (first clause of a long sentence) by `tts.Speaker` while still being written; pauses restored between pieces. | accepted | Local sound is better (user's words) and 0.6 s per sentence with no network. No Indian-English voice exists in Kokoro (US/UK/Hindi only). Piper not built. |
| 22 | **Reply streaming.** Providers expose `stream()`; `Agent.stream()` yields text pieces; `core/main.py` prints and speaks together, never waiting for the full answer. A tool call still delays the first word (the model calls the tool before writing). Claude provider is not streaming. | accepted | User: print what was recognized, send to the brain at once, print and speak the answer simultaneously. |
| 23 | **Gemini free tier handling.** `EVIE_MODEL` is a comma list (`gemini-3.5-flash-lite,gemini-3.1-flash-lite,gemini-3.5-flash,gemini-2.5-flash`); SDK retries off (`attempts=1`); a 429 sidelines that model for Google's `retry in Ns`; if all are limited Evie says "My brain is busy"; a failed turn is removed from history. | accepted | The free tier is ~5 requests/min per model and a tool turn costs 2; the SDK's silent retry caused 9-16 s waits and crashes. A paid key removes the limit. |
| 24 | **Repo layout by domain.** `tools/` and `services/` have one folder per domain (music, web, system, info, voice); `core/` has agent, router, registry, prompts, main; `utils/` has config and text; `scripts/` for setup and diagnostics; `docs/handbook/` for users. | accepted | User: flat folders were "swarming"; layered like their Drstore and Senku projects (grouped by domain here, not by controllers/repositories, since Evie has no database or API yet). |
